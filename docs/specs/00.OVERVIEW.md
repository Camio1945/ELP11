# iced_video_player (ELP11) — Specification Overview

## Project Description

ELP11 is a full-featured desktop video player application built with [Iced](https://iced.rs/) (a Rust GUI framework) and [GStreamer](https://gstreamer.freedesktop.org/) for media playback. It supports a wide range of video formats, offers subtitle display (text-based SRT/VTT/ASS and bitmap PGS), integrated dictionary lookups (FreeDictionary API, MyMemory translation, and Youdao via embedded WebView), playlist management, configurable UI themes, and persistent settings with crash-resilient playback position auto-save.

The crate also exposes a reusable library (`iced_video_player`) providing the `Video` media handle and `VideoPlayer` Iced widget for embedding video playback in other Iced applications.

## Tech Stack

- **Language:** Rust (edition 2024)
- **GUI Framework:** Iced 0.14 (with `wgpu`, `image`, `svg`, `advanced`, `tokio` features)
- **Rendering:** wgpu (custom YUV-to-RGB pipeline via WGSL shader)
- **Multimedia:** GStreamer 0.23 (playbin, appsink, VideoMeta)
- **Window / System:** raw-window-handle 0.6, wry 0.43 (WebView), Windows.Media.Ocr (PGS OCR)
- **HTTP Client:** ureq 2
- **Serialization:** serde / serde_json
- **Image I/O:** image 0.25
- **File Dialogs:** rfd 0.15
- **Platform:** Windows (primary), Linux/macOS supported for the library crate

## Architecture Overview

The application follows a **unidirectional data-flow architecture** built on Iced's Elm-like pattern:

```
User Input (keyboard, mouse, file drop, window events)
    │
    ▼
Subscription ──► Message ──► App::dispatch ──► AppState mutation
                                    │
                                    ▼
                                Task<Message> (side effects: open file, HTTP request, etc.)
                                    │
                                    ▼
                                iced::Application::view ──► Element tree
                                    │
                                    ▼
                             iced_wgpu Renderer
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
               Standard Iced     VideoPlayer      Dictionary
               widgets           (custom          WebView
                                 primitive)       (wry)
```

- **AppState** (`app_state.rs`) holds all application state including `VideoState` (NoVideo / Loading / Ready), playback controls, subtitle state, dictionary results, playlist, and settings.
- **Message enum** defines ~40 message variants covering all user interactions and system events.
- **Dispatch** (`app_dispatch.rs`) routes messages to specialized handlers in `app_handlers.rs`, `app_handlers_playlist.rs`, `app_handlers_settings.rs`, and `app_handlers_subtitle.rs`.
- **Subscriptions** in `main.rs` listen for keyboard events, window events (open, file drop), periodic ticks (dictionary WebView polling, position auto-save).
- **View** (`views.rs`) composes the full widget tree: toolbar, video player area, dictionary sidebar, subtitle overlay.
- **GPU Pipeline** (`pipeline.rs`, `shader.wgsl`) implements `iced_wgpu::primitive::Pipeline` for custom YUV-to-RGB rendering of decoded video frames with AV sync correction.

## Design Principles

- **Layered architecture:** Library crate (`iced_video_player`) provides low-level video playback and rendering; the binary crate (ELP11) builds the full application on top.
- **Elm-like unidirectional flow:** State is centralized in `App`; mutations happen only through `Message` variants dispatched via `App::dispatch`.
- **Separation of concerns:** Each feature area (subtitles, dictionary, playlist, settings) has its own handler module and view module.
- **Crash resilience:** Playback position is auto-saved every 5 seconds to disk so a crash never loses more than a few seconds of progress.
- **GPU-accelerated rendering:** Video frames are decoded on a background worker thread and uploaded to wgpu textures for efficient GPU rendering with AV sync correction.
